# Benchmark datapacks

Files in this directory are generated, validated snapshots. They contain public
model metadata and benchmark results only. API keys stay in GitHub Actions
secrets and are never written here or shipped with the CLI.

Both datapacks are published as replaceable assets on the
`benchmark-data-latest` GitHub Release by
`.github/workflows/refresh-benchmarks.yml`. Installed CLIs try
`~/.bullswarm/cache/` first, then the copy bundled in this directory, then
that release URL. A missing network never blocks setup when a bundled file
exists.

## `openrouter-benchmarks.json`

Generated from OpenRouter's benchmarks and models APIs. Schema
`bullswarm.openrouter.benchmarks.v1`.

### OpenRouter per-effort variants

Inspected `.build-inputs/openrouter-models-2026-09-08.json` on 2026-09-09.
180 models carry `benchmarks.artificial_analysis`. Those objects have only
`intelligence_index`, `coding_index`, and `agentic_index` — one object per
model id, 180 unique ids, no duplicate AA rows.

Fields checked and **not** present on the Artificial Analysis records:
`reasoning_effort`, `effort`, `variant`, `reasoning`, `reasoning_level`.

A top-level model `reasoning` object does exist on many models, with
`supported_efforts` and `default_effort`. That describes API capability, not
a per-effort Artificial Analysis score. `buildOpenRouterDatapack` is therefore
unchanged: it still keeps the highest index-total per model.

The same capture's datapack AA rows (`source: "artificial-analysis"`) use
`source`, `model_permaslug`, `display_name`, `intelligence_index`,
`coding_index`, `agentic_index`, `pricing`. Some `display_name` strings
mention effort in prose; that is not a structured marker and is still one
row per model.

## `epoch-benchmarks.json`

Generated by `scripts/refresh-epoch-benchmarks.mjs --input-dir <dir of Epoch
CSVs> --output data/epoch-benchmarks.json` from Epoch AI's
[AI Benchmarking Hub](https://epoch.ai/benchmarks) export
(`https://epoch.ai/data/benchmark_data.zip`). The script does not download or
unzip; CI does that, then points `--input-dir` at the directory that contains
`model_metadata.csv`.

Schema `bullswarm.epoch.benchmarks.v1`:

```json
{
  "schemaVersion": "bullswarm.epoch.benchmarks.v1",
  "capturedAt": "2026-09-09T00:00:00Z",
  "source": {
    "url": "https://epoch.ai/data/benchmark_data.zip",
    "license": "CC BY 4.0",
    "citation": "Epoch AI, 'AI Benchmarking Hub'. Published online at epoch.ai. Retrieved from https://epoch.ai/benchmarks"
  },
  "records": [
    {
      "modelVersion": "grok-4.6_medium",
      "model": "grok-4.6",
      "reasoningLevel": "medium",
      "benchmark": "cursorbench",
      "score": 0.671,
      "costPerTask": 1.28,
      "tokensPerTask": 17942,
      "releaseDate": "2026-08-12",
      "organization": "xAI"
    }
  ]
}
```

| Field | Meaning |
| --- | --- |
| `modelVersion` | Epoch "Model version" string, unmodified |
| `model` | `normalizeModelId(modelVersion)`: lower-case, drop everything before the last `/`, strip a trailing effort token (`low\|medium\|high\|xhigh\|max\|minimal`) and surrounding punctuation, collapse whitespace to `-`. Connector ids such as `relay/gpt-5.6-luna` match `gpt-5.6-luna` through the same function. |
| `reasoningLevel` | Canonical `low\|medium\|high\|xhigh\|max\|minimal`, or `null`. Taken from an explicit "Reasoning level" / "Reasoning effort" column when present and non-empty (`Extra High` → `xhigh`), else from a parenthesised or `_`/`-` suffix on the model version, else `null`. |
| `benchmark` | `cursorbench`, `deepswe`, `arc-agi-2`, or `critpt` |
| `score` | The CSV's native score on the scale below |
| `costPerTask` / `tokensPerTask` | From the CSV when present (cursorbench cost/tokens; deepswe mean cost / mean output tokens; arc-agi-2 cost per task; critpt cost). `null` when the cell is empty. |
| `releaseDate` / `organization` | From the benchmark row, falling back to `model_metadata.csv` |

### Benchmark scales

All four series in this pack are 0–1 fractions in the Epoch CSVs:

- **cursorbench** — `Score` (observed range about 0.32–0.73)
- **deepswe** — `Pass@1` (observed range about 0.02–0.74)
- **arc-agi-2** — `Score` (observed range 0–0.95)
- **critpt** — `Accuracy` (observed range 0–0.32)

### Blended formula

`rungEvidence(datapack, { model, reasoning })` matches records by
`normalizeModelId(model)` and `reasoningLevel === reasoning`. `null` or
`default` matches only rows whose `reasoningLevel` is `null`. It returns
`null` when nothing matches, otherwise:

- `benchmarks` — the scores that exist among the four names
- `blended` — the arithmetic mean of those present scores (missing
  benchmarks are omitted, not treated as zero)
- `costPerTask` / `tokensPerTask` — from the cursorbench row when one exists
- `sources` — `{ benchmark, modelVersion }` for each score used

If Epoch published more than one row for the same `(model, level, benchmark)`,
the first record in the pack is the one `rungEvidence` uses. The pack itself
keeps every CSV row.

### Cross-check against a prior hand computation

Before the first pack was committed (2026-09-09) three rungs were compared with
an independent hand computation over the same CSVs: grok-4.6 at medium,
gpt-5.6-luna at max, and claude-opus-5 at high. Every cursorbench score, cost
per task and tokens per task matched exactly; the deepswe, arc-agi-2 and
critpt scores differed only by the hand computation's three-decimal rounding.
One upstream quirk was found on a row outside that set: `arc_agi_2_external.csv`
carries two `claude-opus-5_max` rows (0.9042 named "Max", 0.8833 named "High");
the pack keeps both and `rungEvidence` uses the first, so that one blended
value depends on record order.

### Refresh job

`.github/workflows/refresh-benchmarks.yml` (daily, and on `workflow_dispatch`):

1. Refresh OpenRouter as before (`OPENROUTER_API_KEY`).
2. `curl -fsSL https://epoch.ai/data/benchmark_data.zip`, unzip, find the
   directory that contains `model_metadata.csv`, run
   `node scripts/refresh-epoch-benchmarks.mjs --input-dir … --output data/epoch-benchmarks.json`.
3. Run `tests/openrouter-models.test.js` and `tests/epoch-benchmarks.test.js`.
4. `gh release upload benchmark-data-latest data/openrouter-benchmarks.json data/epoch-benchmarks.json --clobber`.
