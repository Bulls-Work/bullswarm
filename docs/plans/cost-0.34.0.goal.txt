Bullswarm 0.34.0: measured token usage, API-rate cost, and subscription cost for every attempt, step, run, and workflow, with each provider owning its own measurement through the existing plugin pattern.

1. Every attempt records measured token usage from the provider itself, never a byte guess when a measurement exists. The order of preference is: the provider's own totals on its event stream (eventStream.usage rules), then a sum over the provider's durable transcript for that session (a new optional provider hook readTranscriptUsage exported from src/providers/<name>/provider.mjs, backed by src/lib/transcripts/<name>.js promoted from scripts/cost-audit with their dedup rules intact), then the utf8-bytes/4 estimate, then unknown. tokenSource names which one was used. Codex, claude-code, and grok are all covered. Token classes are standardRead, cacheRead, cacheWrite5m, cacheWrite1h, output, and reasoning where the provider reports it.
2. Every attempt records an API-rate cost from the model's rate card with a per-class breakdown, including cache-write pricing wherever the vendor publishes a rate, and the rate card's source URL and date. When a class of tokens is unpriced the cost says so instead of silently pricing it at zero.
3. Every attempt records a subscription cost: what share of the pool's quota window it consumed and what that share is worth in dollars of the declared or detected monthly plan price. The share is measured where possible by snapshotting the pool's meter (usedPct per window) at attempt start and end, and estimated otherwise from a per-pool calibration ledger under $BULLSWARM_HOME/calibration/<pool>.json that accumulates observed (apiUsd, quotaDeltaPct) pairs and yields usdPerQuotaPct. Every figure carries a basis string saying whether it was observed, calibrated, or unknown, and unknown is null, never 0.
4. Both costs aggregate correctly from attempt to step to run to workflow, and from run to pool, day, and week: bullswarm run output, bullswarm workflow runs result --json, workflow action show, the Run page, Home, and Stats all show API-rate cost and subscription cost side by side with the basis, through one shared formatter, so an estimate can never render as a measurement.
5. bullswarm workflow reprice back-fills historical attempts from transcripts using the provider hooks, dry-run by default, with --apply, --since, and --pool, writes tokenSource transcript-summed on a match and unknown with null cost on no match or an ambiguous match, then rewrites the rollups and history index.
6. bullswarm provider validate warns when a connector has an eventStream but no usage rules, or a pricing block without cache-write rates, and the provider contract docs, the guide, the CHANGELOG 0.34.0 section, and the design record docs/design/cost-0.34.0/ describe the new hooks, fields, and formulas.
7. Unit tests use real captured fixtures (a real Codex rollout excerpt, real grok unified.jsonl rows, a real claude-code result event) and npm test passes.
