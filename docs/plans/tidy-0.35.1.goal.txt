Bullswarm 0.35.1: a UX tidy-up of the dashboard after the owner reviewed 0.35.0 on a phone (55 columns), plus one correctness fix that every duration depends on. Pricing recovery is NOT in scope (that is 0.35.2); unknown money stays an honest dash.

[owner request, paraphrased] Tidy the dashboard after the phone review: Home shows a few clear cards and one plain line per licence; a single `bullswarm run` task and a workflow step render identically; the Run page plan summary becomes compact boxes; the Step page merges into task, activity, result and cost with a readable overview by default and a detail toggle; and durations count only minutes where at least one agent is working.

1. Active minutes replace wall span everywhere a duration is shown. `minutes.active` = the union of all attempt intervals of the run (a minute counts once when ≥1 agent is working, never when none is); `minutes.span` = first start to last finish, kept as a secondary fact only. Home rows, Runs rows, the Run header, phase header durations, timeline phase durations, and the Stats median/longest duration all use `minutes.active`; worker-minutes (sum of attempt clocks) are unchanged. `workflow reprice` recomputes stored `minutes` for terminal runs so old records are corrected. Each timeline attempt row shows its own attempt's duration (today three `accept` attempts all show 28m22s).
2. Home leads with three cards for today's top runs (active runs first, then the most recently finished), each showing name, project, status and verdict, active minutes, steps done/total and the money pair; the cards flow side by side at 120/200 columns and stack at 55. The licence block becomes one plain-words line per pool (pool · worker-minutes · share of the weekly window · API · subscription) with no abbreviations like "wf % (est.)". The running and budget sections stay. The full run list lives on Runs only.
3. The Run page plan block is compact boxes that flow across the width, one per phase, each showing the phase name and done/total with a status glyph, no per-step rows. Timeline rows carry pool · model · effort. Phase and run durations use active minutes.
4. The Step page has, in order: header (identity, verdict, pool · model · effort, active duration), task (prompt and task merged, first lines with expand), activity, result (output, artifacts and outcome/verification merged), cost (money pair, tokens, budget merged). A toggle key switches overview ↔ detail; overview is the default. Overview activity is turn-based: each agent response as a row, then one line summarising the atomic events between responses (N commands · M files read · K edits · E errors, from real event kinds), then the next response; Enter on a turn expands its atomic events in place. Detail shows today's atomic capture-order log with filters, every technical field and full artifact paths.
5. A single `bullswarm run` task page renders through the same step model and view via an adapter from the task record, so it has the same header, blocks, toggle and activity; the thin "task / artifacts" page is removed.
6. Frames from the real snapshot home at 55, 120 and 200 columns are saved under docs/design/tidy-0.35.1/frames/real-*.txt for Home, Run (running and finished), Step overview and detail (running, finished, failed) and a single task page; no line exceeds its width; the toggle and expand keys work through the dashboard key handler.
7. docs/guide/observing.md and docs/guide/cost.md describe the pages, the toggle, and active vs span minutes; CHANGELOG.md gains `## 0.35.1`; tests use real fixtures; `npm test` passes (the three known load-sensitive tests — Home paints in under 50 ms, real V2 CLI SIGKILL, interactive TUI spinner repaint — must pass when run alone).
