Bullswarm 0.35.2 (providers part): the two contrib providers, opencode and command-code, gain the same two capture layers the first-class providers have — live event-stream usage rules where their stream really carries usage, and a durable-transcript reader — so the 594 attempts on their pools (opencode2* 478, command-code 116, counted by `workflow reprice` on 2026-09-20) stop being "cost unknown" wherever a real record exists. Real data only: never invent a token count, a model price or a fixture; a price needs a cited public source and date or the API figure stays unknown; a free model prices at $0 only when the cited card says so.

Facts already established: opencode keeps every session in the sqlite database ~/.local/share/opencode/opencode.db (3.3 GB, WAL mode; tables session, message, part; message.data is JSON with tokens{input,output,reasoning,cache{read,write}}, modelID, providerID, cost, path.cwd, time; the session row has directory, model, tokens_* and cost). Node 22.23 ships `node:sqlite`; open the database read-only in place, never copy it. command-code keeps Claude-Code-style transcripts under ~/.commandcode/projects/<cwd-slug>/<session-id>.jsonl (lines typed session, session_info, message) plus sessions/ and history.jsonl; message lines carry `"usage":{"inputTokens","outputTokens","cacheReadTokens","cacheWriteTokens","costUsd"}` (24 such blocks in one real 200 KB session file, e.g. inputTokens 15835, outputTokens 349, cacheReadTokens 7552, costUsd 0.007219231), so command-code usage and even the CLI's own cost figure are recoverable; the study confirms the model id field and how inputTokens relates to cacheReadTokens. The live streams are `opencode run --format json` and `command-code --output-format json`, with tool/response rules already in providers/contrib/<name>/connector.json but no `usage` rules and no `readTranscriptUsage` hook in provider.mjs. src/lib/providers.js `transcriptReaderFor(providers, pool)` already resolves a pool (including account pools such as opencode2:kaihk-2) to its provider's hook, but src/lib/transcripts/index.js and `workflow reprice` still hard-code claude-code, codex and grok.

1. opencode transcript reader: providers/contrib/opencode/provider.mjs exports `buildTranscriptIndex` and `readTranscriptUsage` over opencode.db via node:sqlite (read-only, in place), returning the token classes standardRead, cacheRead, cacheWrite, output, reasoning, the model id, cwd and time bounds; an attempt matches a session by cwd + time window, then by the task text in the session's first user message when several fit; ambiguous stays unknown. Fixtures are real rows exported from the database (a handful of messages, redacted of nothing but private text if needed and marked as such).
2. command-code transcript reader: the same hook pair over ~/.commandcode/projects, following what the study proves the files contain; if they carry no token usage, the reader returns null with a documented reason and the requirement is met by that documentation plus the subscription path in 5.
3. Live stream usage rules: for each of the two connectors, either `usage` rules that a real captured stream file (a `stream-*.jsonl` for an opencode2* or command-code attempt in the test home) proves correct, or a documented statement that the stream carries no usage, with the file inspected named.
4. Registry: transcript readers come from the loaded providers (first-class and contrib) instead of a hard-coded list, in src/lib/transcripts/index.js, src/lib/watch.js and src/workflow/reprice.js, so reprice prices opencode2*, opencode2:kaihk-*, and command-code attempts; pool → provider resolution reuses providerFor/transcriptReaderFor.
5. Money honesty: model rate cards in the two connectors only with a cited source URL and date per model; command-code's credit meter (readUsage already parses credits) yields an observed subscription basis where meter snapshots exist; otherwise the figure is unknown, never zero.
6. Evidence: `workflow reprice` dry-run against a copy of the test home reports how many of the opencode2*/command-code attempts now resolve (exact numbers quoted), and two attempts are re-derived by hand from the database or the jsonl and match; `npm test` passes (the three known load-sensitive tests — Home paints in under 50 ms, real V2 CLI SIGKILL, interactive TUI spinner repaint — must pass when run alone).
7. Docs: docs/reference/providers.md documents the two readers and the registry rule; docs/guide/cost.md names which pools recover history and which never can (grok before 2026-09-14, anything with no transcript); the changelog text for 0.35.2 is drafted in docs/design/providers-0.35.2/CHANGELOG-draft.md (CHANGELOG.md itself is not edited in this run to avoid a merge conflict with 0.35.1).
