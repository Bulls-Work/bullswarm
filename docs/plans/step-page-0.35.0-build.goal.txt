Bullswarm 0.35.0: the dashboard Step detail page rebuilt to the design record in docs/design/step-page-0.35.0/, as rich as project-n's session view, on top of the 0.34.0 cost record.

1. The Step page is extracted out of src/workflow/dashboard.js into src/workflow/step-model.js (pure data shaping, no rendering) and src/workflow/step-view.js (rendering and hit regions, no file I/O), following the Budget and Stats model/view split, with the existing dashboard tests still passing and the rendered Step page byte-identical at the extraction checkpoint.
2. The normalized attempt stream carries, additively and only where a provider proves them from real output, stable turn, event and tool-call identifiers, tool name, arguments and result, provider timestamp, duration, per-event usage, and parent or subagent identifiers; old stream files stay readable and missing fields are omitted, never invented.
3. The new Step page shows, in the design record's priority order: identity and verdict with execution success kept distinct from independent verification; the selected attempt; attempt history across retries and failures; the route explanation; the 0.34.0 money pair and token classes with basis, unknown rendered as a dash and never as zero or a bare dollar sign; a live activity feed from the stream file with a minimap, follow-tail, selection and filters; selected event detail; durable outcome and requirement evidence; prompt preview and artifact paths; and an explicit unavailable state for every field capture cannot supply.
4. The page lays out at 55, 120 and 200 columns for running, finished-verified and failed-with-two-attempts steps with no line exceeding the width, and the keyboard actions in the design record work: arrows select, Enter opens detail, Tab cycles sections, Space toggles follow, a, o, p jump, e and t filter, Esc closes.
5. docs/guide/observing.md, docs/reference/providers.md and CHANGELOG.md 0.35.0 describe the page, the keys, the degradation states, and which providers supply which optional stream fields.
6. Tests: pure model tests on real fixtures (running stream, finished result, two failed attempts, malformed and missing stream, new and legacy cost records) and width-bounded view tests for all nine frames, and npm test passes.
